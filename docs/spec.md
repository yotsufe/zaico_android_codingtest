# 仕様

**このアプリが今どう動くかを記述する、唯一の正。**

実装を変えたら、同じ PR でこの文書も更新する。仕様と実装がずれたら、**この文書が間違い**として扱う。

> **ここに書くのは、利用者から観測できることだけ。**
> エンドポイントの形、JSON の構造、クラス構成といった「どう作るか」は
> [design.md](design.md) が持つ。役割分担は
> [CLAUDE.md](../CLAUDE.md#ドキュメントの役割分担) を参照。

各項目の `→` は、その振る舞いを固定しているテスト。無いものは自動テストで守られていない。

> **ViewModel のテストが固定するのは「状態」であって、画面に出る文言や可視・不可視ではない。**
> Activity / Fragment はテストしない方針（[design.md](design.md#テスト戦略)）のため、
> 「どの状態でどう描画するか」は実機確認でしか守られていない。`→` が付いていても、
> 文言そのものが保証されているわけではない。

## 1. 在庫一覧

起動時に最初に表示される画面。アプリバーのタイトルは「在庫一覧」。

### 1.1 表示

- 起動すると在庫一覧を取得して表示する
- 各行に **ID とタイトル**を表示する
- 行をタップすると、その在庫の詳細画面へ遷移する
- 右下の FAB から在庫データ作成画面を開く
- 読み込み中はプログレスバーを表示する
- 在庫が 1 件も無いときは「在庫データがありません」を表示する
  （0 件であることの判定 → `InventoriesViewModelTest`）
  - **取得に失敗した場合とは区別する。** 0 件は成功であり、エラーではない

### 1.2 再読み込み

- 在庫データ作成に**成功したときだけ**読み込み直す（作成の成否の判定は UI 層にあり**未テスト**）
  - 作成画面をツールバーの戻るで閉じた場合は読み込み直さない（→ 3.3）
- **読み込みに成功していれば、画面復帰や回転では読み込み直さない** → `InventoriesViewModelTest`
  - 無駄に API を叩かないため
- **読み込みに失敗していれば、画面復帰や回転のたびに読み込み直す** → `InventoriesViewModelTest`
  - 失敗したままアプリを離れて戻ったときの再試行を兼ねる
- 読み込み直しの結果、**先頭の在庫が入れ替わったときだけ**スクロール位置を先頭へ戻す
  - 作成した在庫は先頭に来るが、スクロール位置が下のままだと気づけない
  - 一方で無条件に戻すと、アプリに復帰しただけで位置を失う

### 1.3 読み飛ばし

- 一覧の中に形が想定と違う在庫があっても、**残りは表示する** → `ZaicoInventoryRepositoryTest`
  - 1 件の不正データで全件を失わないため
- 読み飛ばした件数を「N 件の在庫データを読み取れませんでした」と通知する
  （件数を状態に載せること → `InventoriesViewModelTest`）
  - 黙って減らすと在庫が欠けたことに気づけない
- **同じ読み飛ばしを二度通知しない。** 再取得を伴わない画面復帰では出ない
  → `InventoriesViewModelTest`

### 1.4 失敗

- 取得に失敗すると「在庫一覧を取得できませんでした: <理由>」を表示する
  （失敗状態への遷移 → `InventoriesViewModelTest`）
- **失敗しても、直前に表示していた一覧は消えない。** 通知を出すだけで中身は差し替えない
- **同じエラーを二度通知しない** → `InventoriesViewModelTest`
  - ただし 1.2 のとおり、失敗状態のまま復帰・回転すると**再取得が走る**。
    それがまた失敗すれば、**新しいエラーとして再び通知される**

### 1.5 検索（未対応）

- **検索窓が表示されているが、機能していない。** 文字を入力しても一覧は変わらない
- 検索窓を読み上げても、**何を入力する欄なのか分からない**

## 2. 在庫詳細

一覧の行をタップすると開く。アプリバーのタイトルは「在庫詳細」。

- 対象の在庫の **ID・タイトル・数量**を表示する
- 在庫画像の欄には、**API の画像ではなく固定のプレースホルダ画像**（`drawable/no_image`）を表示する。
  読み上げ用の `contentDescription` は「画像なし」（画面に文字としては出ない）
- 読み込み中はプログレスバーを表示する
- ツールバーの戻るで一覧へ戻る
- **読み込みに成功していれば、画面回転で読み込み直さない** → `InventoryDetailViewModelTest`
  - 表示する在庫は途中で変わらないため
- **読み込みに失敗していれば、画面回転のたびに読み込み直す** → `InventoryDetailViewModelTest`
- 取得に失敗すると「在庫詳細を取得できませんでした: <理由>」を表示する
  （失敗状態への遷移 → `InventoryDetailViewModelTest`）
- **同じエラーを二度通知しない** → `InventoryDetailViewModelTest`
  - ただし失敗状態のまま回転すると再取得が走り、また失敗すれば新しいエラーとして通知される
- **一覧と違い、形が想定と違う在庫は読み飛ばさない。** 読み取れなければエラーになる（→ 5.2）

## 3. 在庫データ作成

一覧の FAB から開く。アプリバーのタイトルは「在庫データ作成」。

### 3.1 入力と検証

- 入力するのは**タイトルのみ**（送信ボディが `{"title": ...}` であること → `ZaicoInventoryRepositoryTest`）
- タイトルが空、または空白だけのとき、**通信せずに**入力欄へ
  「タイトルを入力してください」を表示する → `CreateInventoryViewModelTest`
- タイトルの前後の空白は取り除いて送信する → `CreateInventoryViewModelTest`

### 3.2 送信

- 送信中はプログレスバーを表示し、**入力欄と登録ボタンを無効化する**
  （送信中であることを状態に出すこと → `CreateInventoryViewModelTest`。無効化そのものは未テスト）
  - 二重送信を防ぐため
- 成功すると「在庫データを作成しました」を表示して画面を閉じ、一覧へ戻る。
  一覧は作成された在庫を含めて読み込み直される（→ 1.2）
- 失敗すると「在庫データを作成できませんでした: <理由>」を表示する。
  **画面は閉じない**（入力を失わないため。失敗状態への遷移 → `CreateInventoryViewModelTest`）
- 結果の表示後は状態を戻す。画面回転で同じ通知が再表示されない → `CreateInventoryViewModelTest`

### 3.3 中断

- ツールバーの戻るで閉じると、**入力は破棄される**。確認は出ない
- このとき一覧は読み込み直されない（作成していないため）

## 4. エラーの表示

失敗の理由は、次のように文言へ変換して表示する。

| 原因 | 表示 |
|---|---|
| API トークン未設定 | 「API トークンが設定されていません。local.properties に zaico.apiToken を設定してください。」 |
| API がエラーを返した | API が返した理由をそのまま出す → `ZaicoApiTest` |
| API がエラーを返したが理由を取り出せない | HTTP のステータス文字列（例: `500 Internal Server Error`） → `ZaicoApiTest` |
| 上記以外 | 例外の `message`。`message` が無ければ例外のクラス名 |

- API トークンが未設定のとき、**通信を試みずに**例外を投げる → `ZaicoApiTest`

レスポンスの形が想定と違う場合は、その理由が**日本語で** `<理由>` に出る
（例: 「レスポンスに data が含まれていません」）。

### 未対応

- **通信断などの例外が英語のまま出る。** `UnknownHostException` などが `message` そのままで表示される

## 5. データの取得元

zaico 公開 API v2 から取得する。**エンドポイントの形や JSON の構造は
[design.md](design.md#api-バージョン) が持つ。** ここには利用者から観測できる帰結だけを書く。

### 5.1 起動後の最初の 1 回だけ余分に通信する

在庫のエンドポイントは所属会社の ID を必要とするが、アプリはそれを知らない。
そのため**初回の在庫アクセス時に、会社を問い合わせる通信が 1 回増える**。

- 一度取得したら**プロセスが生きている間は保持する**。2 回目以降は問い合わせない → `CompanyIdProviderTest`
- 一覧と詳細が同時に取得を始めても、**問い合わせは 1 回だけ** → `CompanyIdProviderTest`
- 失敗したら保持しない。次の操作で問い合わせ直す → `CompanyIdProviderTest`
- 会社が 1 件も無いと「利用可能な会社が見つかりませんでした」で失敗する → `CompanyIdProviderTest`
- **アプリを再起動すると問い合わせ直す**（保存していないため）

### 5.2 データが欠けていたときの表示

| 欠けたもの | 画面 |
|---|---|
| タイトル | **空欄**で表示する → `ZaicoApiTest` |
| 数量 | **空欄**で表示する → `ZaicoApiTest` |
| ID | その在庫は**表示できない**（下記） → `ZaicoApiTest` |

ID を読み取れない在庫の扱いは、画面によって違う。

| | 扱い |
|---|---|
| 一覧 | **その 1 件だけ読み飛ばす。** 残りは表示し、件数を通知する（→ 1.3） → `ZaicoInventoryRepositoryTest` |
| 詳細 | **エラーになる。** 読み飛ばす対象が無いため |

## 6. 対象環境

- minSdk 28 / targetSdk 35
- 画面の向きは縦横とも対応（回転しても状態を保持する）
- 日本語のみ。他言語のリソースは持たない
- ダークテーマは**未対応**。区切り線が暗い背景に埋もれる
