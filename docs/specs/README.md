# 変更 spec

**1 つの変更につき 1 ファイル。実装を始める前に書く。**

[TEMPLATE.md](TEMPLATE.md) をコピーして埋める。
ドキュメント全体の役割分担は [CLAUDE.md](../../CLAUDE.md#ドキュメントの役割分担) を参照。

## 凍結のタイミング

**マージした時点で凍結する。それまでは PR の一部なので、いくらでも書き換えてよい。**

最後の書き込みは `状態` と `PR` 番号の確定（[CLAUDE.md の進め方](../../CLAUDE.md#進め方) ステップ 8）。
それ以降は書き換えない。

そう決めておくことで、[design.md](../design.md) が戒めている
「二重に持つと片方の更新が漏れ、事実と逆の記述が生まれる」状態を避けられる。
更新対象でないものは、古くなりようがない。

ADR（Architecture Decision Record）と同じ扱い方。
「今どうなっているか」を知りたい人は [spec.md](../spec.md) を読む。

## 命名

```
NNN-kebab-case-name.md
```

`NNN` は 3 桁の連番。**`001` から始める。** 欠番が出ても詰めない。

**一覧はこの文書に持たない。** ファイル名が連番とタイトルを兼ねているので、
ディレクトリを見れば足りる。一覧表を置くと各ファイルの状態と二重管理になり、必ず腐る。
